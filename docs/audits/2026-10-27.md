## Confirmed findings

### B-001 — 3D guide timeout

The complete browser suite is enabled for PRs and sharded across runners. In run 40546232814 the `Look around in 3D` test reached “Back to 2D to edit the plan” but the tour bar stayed visible beyond 240 seconds on both attempts. No page error was recorded. Software-rendering contention is a possible contributor, not an established cause. Fix the cause and demonstrate a successful complete browser run.

### B-002 — diagonal interior partitions

`src/app/three/site-model.ts` builds each interior partition as a vertical Z box only when its X coordinates match, otherwise as an X-aligned box centred between the endpoints. A diagonal partition therefore does not follow its plan segment. A temporary test used a 10 × 8 m building at the origin with basement height 3 and a partition from `(1,1)` to `(8,6)` in the floor's min-corner coordinates. At local/world `(-3,-2,-2.285714)`, on that segment, `model.collider.hit` returned `false` instead of `true`. This affects interior partition rendering and collision independently of the new diagonal perimeter.

### B-003 — basement outline coordinate limit

`moveBasementVertex` accepts finite simple outlines without the ±300 m coordinate bound used by `cleanBasement` in `src/app/core/site-spec.ts`. A temporary test moved vertex 1 of a 10 × 8 m basement to `(301,-4)`: the editor function returned `true`, but sanitizing its JSON copy dropped `basement.outline`. The discrepancy can replace the saved shape with the inherited outline on import. Align edit and import validation, and test boundary values.

## Other observations and open verification

- The AI server configuration is serialized to `localStorage`, including its optional token. This is an explicit implementation fact, not proof of an exploit; review it against intended privacy and disclosure. Race relay configuration instead requires a token and restricts origins; its tests cover authorization and payload limits, not a full security review.
- Warehouse wall/terrain depth bias is a candidate mitigation; gallery roads, tunnel portals, basement lighting and several slope/intersection cases still need real-browser visual review. Static screenshots and geometry tests are not sufficient to establish flicker-free behavior.
- Diagonal basement outlines are implemented with 2D vertex controls, but Cut/Wing on diagonal outlines, perimeter holes/islands and 3D vertex handles are not. Some vertex edits are rejected to protect existing content.
- Racing has unit, integration and mocked browser checks; two-device GPS, clock alignment, disconnect/rejoin and field latency still need real equipment. Villetta dimensions inferred from photographs still need site review.
- The original working plan mixed old and current statuses. It is archived unchanged; the new backlog is the active ledger. The audit corrected identified stale claims in `AGENTS.md`, README, design and mascot/racing docs. The generated video guides and remaining documentation have not been exhaustively validated visually.
