# Buildings and example bandos

Area notes for OpenBando ([index](../areas.md)). Read before you change this area; the rules and lessons here are as binding as AGENTS.md.

### Ruins, example bandos

- Buildings snapped flush (B-035): two identical wall boxes in one place fight in the depth buffer, visible through windows. `core/flush-walls.ts` `flushWalls` finds wall edges of two buildings on one line (site coordinates, any rotation, shaped buildings too); the later building's wall there is built `FLUSH_INSET` thinner on each face (`Ctx.thin`, only for the walls above ground). Do not "fix" it with a polygon offset: every building's walls already share one.
- `BuildingSpec.ruin` (0..1, absent = intact) is a property, not a kind (`core/ruin.ts`). The roof goes first: `roofRuns` / `roofCells` leave holes in gable, gambrel, vault and flat roofs (each kept part has its own collider, so the holes can be flown through), gone from `ROOFLESS` (0.6); upper slabs go from `NO_SLABS` (0.75). Once the building is open to the sky (past `ROOFLESS`, or `roofless`), each wall loses its upper part along one smooth broken line over the whole building height (`wallTop`, seeded per wall; `wallPieces` cuts each stretch to it) and never has holes lower down. `BuildingSpec.ruinWalls` gives single walls of a rectangle their own level (local sides n/s/e/w; inspector "ruin by wall", AI `set_ruin` with `side`). `BuildingSpec.roofless` makes an open shell at any level; `crenels` adds battlements, none where a wall's top has fallen. Inspector: "ruined %", "open shell", "battlements"; AI: `set_ruin` (ruin percent, roofless, crenels).
- `playground.json` (Playground) is a made-up place built entirely by its section of `build-examples.ts`: hidden, origin 0, 0, ground from brush strokes only (no `terrain.base`), a tunnel, a basement under a floor hole, ruins, seeded trees, and every catalogue block (the script throws if one is unused, so a new block needs a spot there). `core/examples.spec.ts` checks it.
- Example bandos are generated: `npm run examples` (`tools/examples/build-examples.ts`, inputs in `tools/examples/data/`) rebuilds `library/bandos/*.json` byte for byte (ids are renumbered stably), and CI fails when they differ. Change the script, never the JSON.
- Example descriptions appear in the info tooltip beside the Bandos → Examples title; keep hover, focus and tap access, without a separate description row.
- An example's title is its name only ("Bando Villetta", "Bardwell House"): never "(place hidden)" or other status in it, the card already shows "place hidden" (user, 2026-10-29).
- Examples carry a `release` (raise it when an example changes in a way its copies should hear about; `finish(…, release)` in the builder, by hand for `villetta-no-place.json`). "Open a copy" stamps the copy with `derivedFrom: { example, release }`; the Bandos list then says when a newer release is out and offers a fresh copy (`newerExample`). Copies are never changed under the pilot's edits.
- Example bandos live in `library/bandos/*.json` (a SiteSpec plus an `about` line); `tools/build-catalog.mjs` copies them to `public/library/bandos/` and lists them in `public/library/bandos.json`. The Bandos list offers them under Examples ("Open a copy" imports them like a file). The blocks they use (`abando/vault-shed`, `abando/sign-tower`, `abando/water-tower`, `abando/cage-ladder`, `abando/bridge`) are ordinary catalogue blocks. `core/examples.spec.ts` checks every published example loads.

### Bardwell House

- `library/bandos/bardwell-house-no-place.json` is built by `npm run examples` from `tools/examples/data/bardwell-house.hidden.json`: the app's own export of the generated bando with its place hidden (embedded relative ground, no coordinates, no map names). To refresh the input, export the pilot's private bando hidden in the app and check the file has no coordinates, terrain key or names before committing it; never commit the private original.
- The refinements in its section of `build-examples.ts` are measured on the pilot's top views, scaled on the generated house and barn (≈ 8 cm a pixel): gambrel house split into the gambrel block and a flat-roofed south-east wing, gambrel barn, the store, three sheds, the patio, its brick wall (in three lengths so it steps down the slope), the drive's wooden fence 3 m off the drive's centre line, a camper and a car. The map's "concrete" over the west fields was a tagging error and is dropped. The pilot's FPV simulators have their own model of the place: game assets, not used.

### Villetta measured example

- `library/bandos/villetta-no-place.json` remains the place-hidden source (no private coordinate inputs); edit it there, never the published copy under `public/` (`npm run examples` copies the source over it). Release 13 raises the greenhouse crown to approximately 11.2 m above its raised floor (dimensionless vault ratio 1.1). Release 12 (2026-10-30, owner's photo) adds the deciduous tree at the greenhouse's south-west corner (7 m, crown 3.2 m, 4 m out on the corner's diagonal, so the crown clears the frame). Its release 11 raises the greenhouse floor and end frame by an estimated 0.35 m above its levelled pad; release 10 applies the October survey, facade, central roof-strip and revised clear column spacing; interpretations live in the archived working plan and remaining checks in the backlog. Keep its exported counterpart in `public/library/` generated with `tools/build-catalog.mjs`.
- Greenhouse `BuildingSpec.ribSpacing` optionally sets a measured pitch; absent = the old evenly spaced ~2.5 m ribs. `vaultK` sets the ellipse crown (`width / 2 * vaultK + baseY`), not `height`. Bare frames are intact; only glazed frames get a torn stretch.
- Store vault crown is wall height + `((width - roofCenterStrip) / roofCount / 2) * vaultK` when `roofTurn` is true; `roofRise` alone does not set a barrel crown. Annex slabs are centred on `baseY` with thickness 0.20 m; a measured underside of 6.20 m means baseY 6.30 m.
- `abando/cage-ladder` v2 is the reusable open cage, not a solid cylinder. Refresh Villetta's fixture from this block, never maintain an independent ladder shape list. Regenerate Playground and bump its release when this shared placement changes.
