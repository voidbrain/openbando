## Comparison

| Concept | Disposition | Level | Why | Why not | Evidence |
|---|---|---|---|---|---|
| Browser-only, no required backend; personal data stays on the device | adopt (keep) | project | Matches the privacy rules (private places never leave the device; typed coordinates are parsed locally) and costs no server | — | README; [sharing](../../agents/areas/sharing.md); outside local-first practice treats the device as the primary copy ([web.dev storage guide](https://web.dev/articles/storage-for-the-web)) |
| IndexedDB for structured records, with large binary files elsewhere | adopt (keep) | project | Outside guidance is IndexedDB for records, the Origin Private File System for file-like content; bandos and blocks are records | — | [web.dev](https://web.dev/articles/storage-for-the-web); [RxDB storage comparison](https://rxdb.info/articles/localstorage-indexeddb-cookies-opfs-sqlite-wasm.md) (vendor) |
| Origin Private File System for the cached real ground and other large blobs | watch | project | Faster bulk writes from a worker; avoids the IndexedDB value-size path for big terrain tiles | No measured problem today; the synchronous handle is worker-only, so a move means a worker and a migration of cached data. Reconsider when a cache write or load is measured slow | [DEV: OPFS vs IndexedDB](https://dev.to/habibthadev/opfs-vs-indexeddb-241k); [web.dev](https://web.dev/articles/storage-for-the-web) |
| Ask the browser for persistent storage (`navigator.storage.persist`) | watch | project | Both IndexedDB and OPFS can be evicted under storage pressure; a built bando is hours of work | "Back up all" already gives a manual copy; whether eviction has bitten a user is unknown. Reconsider on a reported loss | [web.dev](https://web.dev/articles/storage-for-the-web) |
| WebGPU renderer with WebGL 2 fallback | watch | project | The outside direction for Three.js; better throughput for large scenes | The project's sources disagree on maturity, and the fallback covers standard features but not compute; CI runs software WebGL, so a switch would need its own e2e path. Reconsider when the renderer's status is stable or a frame-time limit is measured | [three.js WebGPURenderer manual](https://threejs.org/manual/en/webgpurenderer); [three.js forum](https://discourse.threejs.org/t/webgpurenderer-forcewebgl-true-vs-webglrenderer/87805/2) |
| CRDT sync (Yjs, Automerge) for shared bandos | reject (for now) | project | Would allow two pilots to edit one bando | Sharing is a one-way export of a copy, and a hidden copy must never carry the place: a live sync document would widen what leaves the device. Outside writers note CRDTs are often unnecessary for single-author apps. Reconsider if co-editing becomes a requirement | [comparison of JavaScript CRDTs](https://blog.notmyidea.org/a-comparison-of-javascript-crdts.html); [local-first for solo apps](https://dev.to/raxxostudios/local-first-architecture-for-solo-apps-when-crdts-help-and-when-they-hurt-4pj0) |
